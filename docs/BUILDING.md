# Building Kosh from source

Kosh is an [Expo](https://docs.expo.dev/) (SDK 58) app with a local native module, so it needs a **development build**; Expo Go can't run it. The `android/` folder is generated by `expo prebuild` (Continuous Native Generation) and is never committed; don't edit it by hand.

## Prerequisites

- **Node.js 20 or newer** (CI uses Node 24) and npm
- **JDK 17** (e.g. Temurin)
- **Android SDK** with platform tools: install [Android Studio](https://developer.android.com/studio), or the command-line tools, and set `ANDROID_HOME`
- An Android phone with USB debugging on, or an emulator. SMS reading and usage stats are best tested on a real phone.

## Get the code and install

```bash
git clone https://github.com/Abhijat-Abhijat/kosh.git
cd kosh
npm ci
```

## Environment (optional)

Kosh needs no configuration to run. The only optional variable is crash reporting:

```bash
cp .env.example .env
```

| Variable | Purpose |
| --- | --- |
| `EXPO_PUBLIC_SENTRY_DSN` | Optional. If set, crashes are reported to your own Sentry project. Leave empty for no crash reporting. Official releases leave it empty. |

`.env` is git-ignored. `EXPO_PUBLIC_*` values are compiled into the app and are not secret.

## Run on a phone

```bash
npx expo run:android      # same as: npm run android
```

This runs `expo prebuild`, builds a debug APK with Gradle, installs it and starts Metro. After the first build, `npx expo start` is enough for JavaScript-only changes. Rebuild with `npx expo run:android` after changing `app.json`, adding a native package, or editing `modules/kosh-native`.

## Checks

```bash
npm run typecheck
npm run lint
npm test
```

## Windows: long paths

On Windows, the C++ codegen for `react-native-gesture-handler` (and a few other packages) creates paths longer than 260 characters, and the build fails with "file name too long" or CMake/Ninja errors. Either:

1. Enable long paths (both are needed), then reboot:
   ```powershell
   git config --global core.longpaths true
   # In an elevated PowerShell:
   New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force
   ```
   Keep the project close to the drive root (e.g. `C:\src\kosh`) to keep paths short.
2. Or build in **WSL 2** (Ubuntu) with the Linux Android SDK, or
3. Let CI build it: push a branch and run the **Release APK** workflow manually (Actions → Release APK → Run workflow); the APK is attached as a workflow artifact.

## Release APK locally

```bash
npx expo prebuild --platform android --no-install
cd android
./gradlew assembleRelease \
  -Pandroid.injected.signing.store.file=/absolute/path/to/kosh-release.jks \
  -Pandroid.injected.signing.store.password=... \
  -Pandroid.injected.signing.key.alias=... \
  -Pandroid.injected.signing.key.password=...
```

The APK is in `android/app/build/outputs/apk/release/app-release.apk`. Without the `-P` signing properties the Expo template signs release builds with the debug key; that's fine for testing but not for distribution.

Set `SENTRY_DISABLE_AUTO_UPLOAD=true` when building release without a Sentry auth token, or the Sentry Gradle step will try to upload source maps.

Create a signing key once with:

```bash
keytool -genkeypair -v -keystore kosh-release.jks -alias kosh -keyalg RSA -keysize 4096 -validity 10000
```

Keep the keystore and passwords safe and **out of git** (`*.jks` and `*.keystore` are ignored). If you lose them, existing users can't update without uninstalling, which deletes their data.

## EAS cloud builds

`eas.json` defines three profiles, all producing APKs:

| Profile | Use |
| --- | --- |
| `development` | Development client for `npx expo start` |
| `preview` | Internal test APK |
| `production` | Release APK (sideload distribution, not Play Store) |

```bash
npx eas-cli@latest build --profile development --platform android
```

You need a free Expo account. EAS manages its own signing key unless you upload yours. Official releases are built by GitHub Actions instead (below).

## How releases are made

1. Update `version` in `app.json` (and `package.json`) and move the `[Unreleased]` notes in `CHANGELOG.md` under the new version.
2. Merge to `main` with CI green.
3. Tag and push: `git tag v0.1.0 && git push origin v0.1.0`.
4. `.github/workflows/release.yml` runs the CI checks (typecheck, lint, tests) first, then: `npm ci` → stamps the tag's version into `app.json` (`versionCode` = `major*10000 + minor*100 + patch`) → `expo prebuild` → `./gradlew assembleRelease` signed with the repository secrets → uploads `kosh-<version>.apk` and `kosh-<version>.apk.sha256` to a GitHub Release. Tags with a hyphen (`v0.2.0-beta.1`) are marked as pre-releases.

## Website (GitHub Pages)

`.github/workflows/pages.yml` publishes `website/` to <https://abhijat-abhijat.github.io/kosh/> on every push to `main` that touches `website/`, and on demand (Actions → Deploy website → Run workflow).

One-time setup: repository Settings → Pages → Build and deployment → Source: **GitHub Actions**. The site has no build step; `404.html` uses `<base href="/kosh/">`, so update it if the repository is renamed or a custom domain is added.

Repository secrets used for signing (Settings → Secrets and variables → Actions):

| Secret | Value |
| --- | --- |
| `KOSH_KEYSTORE_BASE64` | `base64 -w0 kosh-release.jks` |
| `KOSH_KEYSTORE_PASSWORD` | Keystore password |
| `KOSH_KEY_ALIAS` | Key alias (e.g. `kosh`) |
| `KOSH_KEY_PASSWORD` | Key password |

If any secret is missing, the workflow still builds but produces `kosh-<version>-unsigned-debug.apk` (debug-signed) and adds a warning. Don't publish that as a release.
